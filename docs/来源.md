这个 Mod 最早其实只是一个非常简单的 Mod: 让蒸汽流体可以直接驱动 `机械动力` 的锅炉.

简单到什么程度呢? 明明开发环境使用的是 6.0 版本的 `机械动力`, 但实际运行时, 甚至可以在 0.5.1 版本中正常工作, 就连名字最初也只是叫做 `Create: "Steam" Ages`.

是的, 早期的这个名字, 单纯就是为了表达一句话: "蒸汽一定要蒸汽✍️"

再后来, 随着 CMI 的开发, 我们开始重新调整整个蒸汽时代的设计. 原 Mod `机械动力: 蒸汽动力` 自身有一套 HU 系统, 而这套系统与 CMI 的设计理念并不相符, 也让我们在调整蒸汽时代的平衡时遇到了不少问题.

但是, 我又十分中意 `蒸汽动力` 中的蒸汽飞轮(引擎)以及蒸汽生产系统. 因此, 我最终还是决定把 CSA 重新捡起来, 并在原有的基础上重新设计.

一开始, 我并没有急着研究新的蒸汽生产方案, 而是先注册了蒸汽和过热蒸汽这两种流体, 让玩家可以直接在工作盆内通过加热, 搅拌水来获取蒸汽. 与此同时, 我也先把 CMI Core 中的蒸汽锻锤移植了过来.

在移植的过程中, 为了让后续的功能开发和扩展更加方便, 我还额外补充了不少 API 和接口. 等到又陆续制作了几台机器之后, 我才正式开始研究蒸汽生产系统, 以及蒸汽飞轮(引擎)的动力消耗算法.

而这一切, 自然也离不开 AI 的帮助.

我专门写了一份大小达到 27.8 KB, 总计 556 行的 `蒸汽训练词.md`, 然后把它交给了 AI. 当然, 我并没有把整个开发过程完全交给 AI 去处理. 我一直在严格关注它的实现过程, 包括算法设计是否合理, API 的使用方式是否足够规范, 以及第三方开发者在尝试扩展功能时, 会不会因为某些设计而感到难以使用.

毕竟, 我希望这个 Mod 不仅能够满足自己的需求, 也能为其他开发者提供足够方便的扩展能力.

需要说明的是, 我们并没有直接照搬 `蒸汽动力` 的算法. 现在的算法是我们自己设计的, 只是参考了 `蒸汽动力` 这个 Mod 的设计思路. 此外, 我们也借鉴并使用了其中一部分与动画和粒子效果有关的代码.

至于整个 Mod 的模型和纹理, 则都是由我们的开发组重新设计和制作的.

虽然我确实是这个 Mod 最主要的作者和开发者, 但这并不意味着所有工作都是由我一个人完成的. 无论是模型, 纹理, 还是其他方面的协助, 都离不开开发组各位的付出. 所以, 在这里还是要感谢开发组的各位.

另外, 这份训练词本身也不是我一个人写的, 而是我和我的男朋友中微子一起撰写的. 早期的蒸汽生产和动力消耗算法, 也都是在不断尝试中逐步完善的, 当时的设计比现在还要简陋得多.

回头来看, 现在的这些系统并不是一开始就规划好的. 很多设计都是随着开发的推进, 在实际实现和反复调整的过程中才逐渐形成的.

最后, 说说这个 Mod 的名字.

为什么现在它叫做 `机械动力: 来自蒸汽的信`, 但 Mod 内却没有任何与 6.0 版本物流系统有关的内容呢?

一方面, 是因为我个人确实很喜欢这种带有浪漫与奇幻色彩的命名风格. 比如 `月亮与六便士`, `追星星的人`, `追星者`, `创世神的黄昏`, `齿轮不会做梦`, `最后的造梦者` 等等. 相比于单纯描述功能的名字, 这种名字对我来说更有吸引力, 也更容易让人产生一些联想.

另一方面, 也是因为我自己其实不太会玩 6.0 版本的物流系统.

虽然我看过大致的玩法, 但要说如何把蒸汽玩法自然地融入 6.0 的物流体系, 我目前还没有什么特别好的想法. 与其为了让名字和版本对得上, 就硬塞一些自己都不知道该怎么设计的内容, 不如先把蒸汽本身做好.

至少在目前, 我更希望这个 Mod 能够专注于蒸汽生产, 动力消耗, 以及围绕这些系统展开的机器与自动化玩法. 至于未来是否会进一步探索与 6.0 物流系统的结合, 还是以后再说吧. 

毕竟 CMI 的开发和下个整合包的制作都得占用很多时间, 下个整合包是 `NeoForge-1.21.1`, 1.20.1 Mod的移植工作也是一笔很大的时间成本开销.

说到底, 这个 Mod 从最初的一个简单想法, 到现在逐渐拥有自己的蒸汽生产系统, 动力消耗算法和扩展接口, 其实一直都在围绕同一个目标前进: **让蒸汽成为一套真正值得研究和使用的动力体系, 而不只是给锅炉换一种燃料.**
